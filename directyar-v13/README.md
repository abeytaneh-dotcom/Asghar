# دایرکت‌یار ۱.۳ | پنل فارسی اتوماسیون کامنت و دایرکت با شرط فالو

این پروژه دو جزء دارد:

1. **اپ اندروید:** تعریف/ویرایش/حذف قوانین کلیدواژه‌ای، انتخاب محل اجرای قوانین (کامنت، دایرکت، هر دو)، تنظیم متن پاسخ اصلی، پاسخ عمومی و آیدی پست؛ نمایش وضعیت سرور و ارسال تنظیمات به آن. مرورگر داخلی اینستاگرام و Meta Business Suite حفظ شده است.
2. **موتور پایتون روی سرور:** دریافت Webhook امضاشده اینستاگرام، ارسال Private Reply به کامنت، شناسایی دکمه «فالو کردم»، استعلام فالو از Meta، تکرار درخواست فالو تا احراز فالو و سپس ارسال متن اصلی. ثبت و کنترل تکرار در SQLite انجام می‌شود.

## دقیقاً چه اتفاقی می‌افتد؟

**کامنت کلمه کلیدی:**

- کاربر مثلاً زیر ریلز «آموزش» کامنت می‌کند؛ Webhook رسمی کلمه را با قانون ثبت‌شده تطبیق می‌دهد.
- بلافاصله *یک* پاسخ خصوصی اولیه با متن «دوست عزیزم… فالو کن …» و دکمه «فالو کردم ✅» ارسال می‌شود. کاربر نیازی ندارد دوباره «آموزش» بنویسد.
- فقط **بعد از موفقیت ارسال پیام خصوصی**، زیر کامنت پیام قابل ویرایش «دایرکت براتون ارسال شد ✅» ثبت می‌شود.
- با هر بار لمس «فالو کردم»، رویداد جدید به موتور می‌رسد و با API رسمی فیلد `is_user_follow_business` بررسی می‌شود:
  - `false` → همان پیام درخواست فالو و همان دکمه دوباره ارسال می‌شود.
  - `true` → متن اختصاصی همان قانون ارسال و وضعیت انتظار پاک می‌شود.
  - `unknown/error` → **محتوا ارسال نمی‌شود**؛ پیغام «فعلاً امکان تأیید فالو نیست» با دکمه تلاش مجدد می‌آید، اگر ارسال مجاز باشد.
- کلیک تکراری، رویداد تکراری و فشردن دکمه مربوط به قانون قدیمی، نباید پاسخ اصلی را تکراری ارسال کنند.

**دایرکت کلمه کلیدی:** پس از دریافت کلمه، فالو استعلام می‌شود. اگر فالو نیست، دکمه «فالو کردم» ارسال می‌شود و چرخه بالا شروع می‌شود؛ اگر فالو است، پاسخ اصلی فرستاده می‌شود.

## محدودیت عملی و مجوزها

**صرف ورود به Meta Business Suite به معنی دسترسی برنامه‌نویسی نیست.** اتوماسیون واقعی به Meta Developer App، توکن رسمی معتبر، شناسه حرفه‌ای اینستاگرام، مجوزهای مربوط به پیام‌ها و کامنت‌ها، Webhook دریافت پیام/کامنت، و سرور HTTPS قابل دسترس نیاز دارد. تا آن زمان موتور **Dry-run** است و هیچ پیامی در پیج منتشر نمی‌کند. نسخه مرورگری ۱.۲ توان ارسال خودکار نداشت.

- API رسمی Meta قابلیت بررسی `is_user_follow_business` را برای کاربری که تعامل لازم را انجام داده فراهم می‌کند. صرف کامنت به‌تنهایی لزوماً دسترسی به داده فالو نمی‌دهد؛ بررسی روی پاسخ دکمه انجام می‌شود.
- متا معمولاً برای یک کامنت فقط **یک** Private Reply اولیه می‌پذیرد؛ ادامه مکالمه منوط به پاسخ/دکمه مخاطب و پنجره ارسال پیام است.
- نوع دکمه در Private Reply به قابلیت حساب و نسخه API متا بستگی دارد. در محیط واقعی **ارسال دکمه و دریافت رویداد کلیک باید جداگانه آزمایش شوند**؛ اگر Meta درخواست را نپذیرد، موتور آن را به‌عنوان ارسال موفق ثبت نمی‌کند.
- اگر پاسخ عمومی زیر کامنت ناموفق باشد، رویداد «private_sent» باقی می‌ماند، نه «completed». موتور Private Reply را خودسرانه دوباره ارسال نمی‌کند.
- وضعیت فالو منفی فقط زمانی اعلام می‌شود که پاسخ API دقیقاً `false` باشد؛ خطای API به معنی «فالو نکرده» نیست.

## تنظیم سرور

روی یک سرور HTTPS با Python 3.11+، پوشه `backend` را اجرا کنید. برنامه نیاز به بسته خارجی ندارد.

متغیرهای محیطی (فقط روی سرور؛ در سورس، GitHub یا موبایل ذخیره نشوند):

```text
META_VERIFY_TOKEN=<random secret>
META_APP_SECRET=<Meta app secret>
META_IG_ACCESS_TOKEN=<Meta access token>
META_IG_USER_ID=<professional Instagram ID>
DIRECTYAR_ADMIN_KEY=<long random admin key>
DIRECTYAR_LIVE=0
DIRECTYAR_BIND=127.0.0.1
DIRECTYAR_PORT=8080
DIRECTYAR_DB=/secure/persistent/directyar.db
```

دستور:

```bash
python3 backend/server.py
```

دروازه HTTPS/TLS باید `/webhook` را به این سرور متصل کند. در Developer Dashboard آدرس `https://YOUR-DOMAIN/webhook` و `META_VERIFY_TOKEN` را برای تأیید ثبت و رخدادهای messaging، postback، comments را subscribe کنید. اگر مجوزها و آزمون‌ها کامل شدند، `DIRECTYAR_LIVE=1` را **روی سرور** فعال کنید. روشن کردن حالت Live بدون همه اطلاعات لازم انجام نمی‌شود.

در اپ، از «قوانین پاسخ خودکار و شرط فالو → اتصال سرویس خودکار» آدرس HTTPS سرور و کلید مدیریت را وارد کنید؛ سپس «ارسال قوانین به سرور» و «بررسی وضعیت سرور». کلید مدیریت در اندروید **فقط برای همان نشست در حافظه** نگهداری می‌شود و توکن Meta در اپ ذخیره نمی‌شود.

## آزمون

```bash
python3 -m unittest discover -s backend/tests -v
```

تست‌ها مسیر کامنت، تکرار چرخه فالو، عدم ارسال محتوا قبل از `true`، پیام عمومی بعد از ارسال خصوصی، مدیریت رویداد تکراری، پست نامعتبر و وضعیت API نامعلوم را پوشش می‌دهند. این‌ها **آزمون شبیه‌سازی‌شده** هستند، نه اثبات ارسال واقعی در پیج.

## ساخت اندروید

Android SDK 35 / Java 17 / Gradle 8.7:

```bash
gradle --no-daemon assembleDebug
```

خروجی: `app/build/outputs/apk/debug/app-debug.apk`.
نسخه ۱.۳ با شناسه `ir.beytaneh.directyar.v13` جداگانه نصب می‌شود تا نصب قبلی بدون امضای مشترک حذف نشود. اطلاعات نسخه‌های قبلی خودکار منتقل نمی‌شوند.
